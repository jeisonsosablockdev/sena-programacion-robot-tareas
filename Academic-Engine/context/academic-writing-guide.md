# Academic & Technical Writing Guide

> [!NOTE] Purpose
> Standards for academic papers, technical reports, project documentation, and presentations produced within this workspace.

## 1. Technical Documentation Structure

### Project Documentation (README)
1. **Title** — Clear, descriptive project name
2. **Description** — What it does, why it exists (1-2 paragraphs)
3. **Installation** — Step-by-step setup instructions
4. **Usage** — How to run, examples, CLI commands
5. **Architecture** — High-level design, folder structure, diagrams
6. **API Reference** — Endpoints, parameters, responses
7. **Testing** — How to run tests, coverage expectations
8. **Contributing** — Guidelines for collaboration

### Technical Report Structure
1. **Abstract / Executive Summary** — Key findings in 150-250 words
2. **Introduction** — Problem statement, context, objectives
3. **Background / Literature Review** — Prior work, theoretical framework
4. **Methodology** — Approach, tools, data sources, experimental design
5. **Implementation** — Architecture, code design, key decisions
6. **Results** — Findings, metrics, visualizations
7. **Discussion** — Interpretation, limitations, implications
8. **Conclusion** — Summary, future work
9. **References** — Full bibliography (APA 7 or IEEE)
10. **Appendices** — Code listings, raw data, additional diagrams

## 2. Citation Styles

### APA 7 (Default for academic papers)
- In-text: `(Author, Year)` or `Author (Year)`
- With page: `(Author, Year, p. 42)` or `(Author, Year, pp. 42-45)`
- Multiple authors: `(Smith & Jones, 2024)` or `(Smith et al., 2024)` for 3+
- Bibliography: Hanging indent, alphabetical order

### IEEE (For technical/engineering papers)
- In-text: numbered references `[1]`, `[2]`
- Bibliography: numbered list in order of first appearance

## 3. Academic Tone & Voice

### DO
- Use formal, precise language
- Write in third person for academic papers
- Support claims with citations
- Use hedging language: "suggests," "indicates," "appears to"
- Define technical terms on first use
- Use active voice when possible: "The algorithm processes..." vs "...is processed by the algorithm"

### DON'T
- Use colloquialisms or slang
- Make unsupported claims
- Use first person in formal papers (unless explicitly allowed)
- Use vague quantifiers: "a lot," "many," "some" without data
- Use emotional or promotional language
- Plagiarize — always cite sources

## 4. Common Pitfalls

| Pitfall | Fix |
|---|---|
| Run-on sentences | Break into shorter, focused sentences |
| Passive voice overuse | Prefer active voice where clarity improves |
| Vague references ("this," "it") | Name the specific referent |
| Unsupported claims | Add citation or qualify as hypothesis |
| Inconsistent terminology | Define terms in a glossary section |
| Missing transitions | Use connectors: "However," "Furthermore," "In contrast" |

## 5. Vocabulary Guidelines

| Avoid | Prefer |
|---|---|
| "very good" | "effective," "efficient," "robust" |
| "a lot of" | "numerous," "significant," "N instances" |
| "things" | name the specific objects/concepts |
| "get" | "retrieve," "obtain," "acquire," "compute" |
| "stuff" | name the specific items |
| "obviously" | remove — let evidence speak |
| "in order to" | "to" |
