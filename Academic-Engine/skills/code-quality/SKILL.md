# Code Quality

## Purpose
Ensures software meets professional standards: readability, maintainability, testability, and adherence to SOLID design principles.

## When to Use
- Code reviews and QA audits
- Refactoring legacy code or fixing code smells
- Implementing design patterns (GoF)
- Enforcing naming conventions and modularity

## Key Principles
1. **Single Responsibility:** Each class/module has one reason to change.
2. **Clean Naming:** Intention-revealing identifiers without mental mapping.
3. **Small Functions:** Under 20 lines, single level of abstraction.
4. **Boy Scout Rule:** Leave the code cleaner than you found it.
