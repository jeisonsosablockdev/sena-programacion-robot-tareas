# 商业计划书路演PPT技能

> 创建精美、面向投资人的商业计划书/融资方案演示文稿，遵循经过验证的专业模板风格。

## When to Use

Use this skill when:
- 用户需要为投资人制作路演PPT或商业计划书演示文稿
- 用户需要生成包含市场分析和财务预测的公司概览幻灯片
- 用户提及创业融资、投资备忘录演示文稿等需求
- 用户需要中国创业公司风格的融资路演材料（藏青色+白色背景）

Do NOT use this skill if:
- 用户只需要BP大纲而非可编辑PPT → use `fundraising-bp-planner` instead
- 用户需要从结构化JSON生成10页标准PPTX → use `pitch-deck-creator` instead
- 用户需要将已有PPT转为网页HTML → use `deck-web-converter` instead
- 用户需要特定叙事框架（红杉/YC/Raskin）→ use对应框架技能

Typical triggers:
- 「帮我做个融资PPT」「商业计划书怎么做」「路演材料」
- "pitch deck PPT", "business plan presentation", "investor deck"

## Workflow

本工作流遵循六步推进法，共6个步骤：
1. **探查 (Probe)**：动手前先完整读取全部输入，确认目标和约束。
2. **约束 (Constrain)**：验证输入完整性，设定边界和不可降级的交付标准，受阻时换通道。
3. **证据 (Evidence)**：每个数字必须来自输入、具体信源或可复现计算，收集支撑数据。
4. **执行 (Execute)**：调用脚本/API/生成内容，先给影响与结论，再给行动和必要证据。
5. **验证 (Verify)**：用"可能失败"的动作验证——不同于生成路径的方式回读输出。
6. **交付 (Deliver)**：返回结果，清理临时文件。

### Step 1: 探查 (Probe)
完整读取用户提供的全部输入（公司简介、已有文档、参考PDF等），确认目标和约束：
- 公司名称、logo、标语
- 所属行业/赛道
- 融资轮次和目标金额
- 关键指标（营收、增长率、利润率、团队规模、专利数量）
- 产品/服务描述 + 图片（如有）
- 竞争格局（3-5家同行）
- 财务预测（3-5年）
- 团队简介 + 照片
- 市场规模/TAM数据

如果用户提供了文字简介或已有文档，从中提取上述信息。

### Step 2: 约束 (Constrain)
验证输入完整性，设定边界和不可降级的交付标准：
- 默认输出**PPTX**（可编辑的演示文稿）；用户明确指定格式时使用该格式
- 用户要求"可分享的"/"最终版"时，可同时提供PDF
- 所有内容页均为白色背景（`#FFFFFF`），绝不使用深色背景
- 主色调为藏青色 `#1B3A6B`；绿色仅用于图表次要数据系列
- 参考模板采用平铺式结构，各主要章节之间**没有过渡页**，请勿添加章节分隔页
- 受阻时换通道，不降级交付物

### Step 3: 证据 (Evidence)
每个数字必须来自输入、具体信源或可复现计算：
- 市场规模数据需注明来源（行业报告、公开数据、自行测算需说明假设）
- 财务预测需基于用户提供的数据或明确标注为假设
- 竞争格局中的竞品信息需可验证
- 收集支撑数据，不虚构traction、市场规模、客户证据或团队背景

### Step 4: 执行 (Execute)
调用脚本/生成内容，先给影响与结论，再给行动和必要证据。

#### 规划幻灯片结构
将用户内容映射到标准章节流程。阅读 `references/structure_contract.md` 获取完整的层级结构和布局模式。默认的14个章节流程如下：

1. **封面** — 公司标识 + 投资机构品牌 + 视觉冲击力图片
2. **投资亮点** — 6宫格展示核心卖点
3. **市场机遇** — 市场规模图表 + 增长逻辑
4. **行业格局** — 竞争对手图谱/同行对比
5. **公司定位** — 战略支柱/价值主张
6. **核心竞争力** — 优势矩阵
7. **产品组合** — 产品概览 + 技术架构
8. **技术差异化** — 技术路线对比 + 参数表格
9. **团队介绍** — 创始人 + 核心团队 + 顾问委员会
10. **增长预测** — 营收/订单预测图表
11. **愿景/路线图** — 多阶段战略规划
12. **融资方案** — 融资需求 + 资金用途分配
13. **附录** — 支撑数据、产品图片、详细对比
14. **免责声明** — 法律声明 + 联系方式

**适配规则**：跳过用户没有相关内容的章节。如果幻灯片总数超过20页，可将紧密相关的章节合并。对于种子轮公司，第7-9章可以精简；对于成长期公司，第10-12章应更详尽。

#### 应用视觉风格
阅读 `references/style_contract.md` 获取完整的风格规范。核心规则：
- **背景**：所有内容页均为白色（`#FFFFFF`）。绝不使用深色背景。
- **配色方案**：主色调为藏青色 `#1B3A6B`（深蓝色）。绿色**仅**用于图表的次要数据系列（如海外/辅助数据的绿色柱状图）。绿色不作为主色调。
- **页眉**：每页内容页标题下方有一条藏青色水平线（2px）。公司logo固定在每页内容页的右上角。
- **数据可视化**：柱状图/条形图的**主色**为藏青色。绿色仅用于次要数据系列。环形图使用藏青色+绿色（或藏青色+灰色）。
- **强调样式**：关键指标加粗，字号比周围文字大2-4pt。
- **总结横幅**：页面底部全宽藏青色矩形，白色文字展示核心结论。

#### 设计每页幻灯片
为每页幻灯片选择 `references/structure_contract.md` 中定义的布局模式：
- **宫格亮点**（模式A）— 3×2卡片，包含图标、标题和两行要点摘要
- **双图表**（模式B）— 左右并列的两个图表，带深色标题栏
- **对比流程**（模式C）— 水平箭头流程 + 下方对比表格
- **战略支柱**（模式D）— 纵向堆叠：藏青色标签胶囊 + 每行要点列表
- **三栏矩阵**（模式E）— 三个并列模块 + 底部图标网格
- **上下对比**（模式F）— 上下流程图 + 标注框
- **图片网格**（模式G）— 三栏产品图片 + 说明文字
- **底部总结横幅**（模式H）— 藏青色全宽总结横幅

每页设计原则：
- 一页一个核心信息
- 正文最多40-50个汉字或约80个英文单词
- 3-6个高亮数据点
- 优先使用图表/图示，而非文字要点
- 每个论点都应有数据、图表或来源支撑

### Step 5: 验证 (Verify)
用"可能失败"的动作验证——不同于生成路径的方式回读输出：
- 确保所有内容页均为白色背景——无例外
- 确认藏青色在所有页面中均为主色调
- 检查所有图表均以藏青色为主要填充色
- 确认logo位置（右上角）在每页内容页中保持一致
- 确认每页标题下方有藏青色下划线
- 验证文字不会溢出形状边界
- 确认团队成员照片为真实照片，而非通用图标
- 确认产品图片为真实图片，而非占位符
- 请勿添加"严格保密"水印或页脚

### Step 6: 交付 (Deliver)
返回结果，清理临时文件：
- 默认交付PPTX文件；如用户要求可同时提供PDF
- 告知用户输出文件路径
- 说明文件可编辑，建议用户根据实际数据替换占位符

### 中文内容字体策略

当演示文稿包含中文文字时（默认情况）：
- **标题字体**：楷体 / STKaiti（替代方案为思源宋体SC）
- **正文字体**：与标题字体一致（保持单一字体族的统一性）
- **英文/数字补充**：Arial（用于英文术语和数字）
- **加粗强调**：使用该字体的粗体字重，或切换到支持粗体的中文字体（如微软雅黑粗体）

当演示文稿为纯英文时：
- **标题字体**：Georgia 或 Merriweather（衬线体，专业感）
- **正文字体**：与标题同一字体族
- **强调/加粗**：使用同一字体族的粗体字重

## Guardrails

**Anti-patterns**
- NEVER 使用深色背景——所有内容页必须为白色（`#FFFFFF`）
- Do NOT 添加章节分隔页/过渡页——参考模板采用平铺式结构
- Do NOT 将绿色用作主色调——绿色仅用于图表次要数据系列
- NEVER 虚构traction、市场规模、客户证据、团队背景或融资条款
- Do NOT 添加"严格保密"水印或页脚
- Do NOT 使用通用图标代替团队成员真实照片或产品真实图片

**Constraints**
- 所有数字必须来自输入、具体信源或可复现计算
- 未知值留空或标注为待确认，不编造
- 幻灯片总数超过20页时合并紧密相关章节
- 种子轮公司可精简第7-9章；成长期公司应详尽第10-12章
- 正文每页最多40-50个汉字或约80个英文单词
